# 量化节点开发技术文档

## 1. 当前开发状态

量化节点用于在 MLOps 平台中对 HuggingFace 格式的大语言模型执行离线量化。当前代码位于 `model-quantization` 分支，核心功能、平台参数和基础测试已经完成，整体处于“镜像构建与 GPU 联调”阶段。

| 精度与性能基线 | 待完成 | 需补充模型体积、显存、速度和精度对比 |

## 2. 需求分析

### 2.1 功能目标

- 支持本地/PVC 模型目录和 HuggingFace Model ID。
- 支持 GPTQ、AWQ 和 bitsandbytes 三种量化方案。
- 支持平台表单配置量化算法、位宽、分组大小和校准数据。
- 量化结果可保存到共享存储，并能被后续评测、注册和推理节点使用。
- 在离线或网络不稳定环境下，优先使用 PVC 数据集和内嵌校准样本。

### 2.2 可靠性要求

- 输入模型、输出目录和算法参数必须在任务启动阶段完成校验。
- 不允许输入目录与输出目录相同，避免覆盖原始模型。
- 非空输出目录默认禁止覆盖；已有成功清单时允许幂等跳过。
- 任务过程输出结构化阶段日志，失败时保留错误类型和堆栈信息。

## 3. 参数设计

| 参数 | 默认值 | 约束 | 说明 |
|---|---:|---|---|
| `--model` | 必填 | 本地目录或 Model ID | 待量化模型 |
| `--output` | `/mnt/admin/models/quant` | 不能与输入目录相同 | 量化模型输出目录 |
| `--method` | `gptq` | `gptq`、`awq`、`bnb` | 量化算法 |
| `--bits` | `4` | GPTQ：2/3/4/8；AWQ：4；BnB：4/8 | 量化位宽 |
| `--group_size` | `128` | 32/64/128/256 | 仅 GPTQ 使用 |
| `--dataset` | `wikitext2` | 目录、CSV、JSON、JSONL、TXT 或 HF 数据集 | GPTQ/AWQ 校准集 |
| `--nsamples` | `128` | 平台 16～1024 | 校准样本数 |
| `--force` | `false` | 布尔值 | 是否允许复用非空输出目录 |

平台表单仅开放 4/8 bit；更细的 GPTQ 位宽可通过 CLI 使用。AWQ 选择 8 bit 时会在模型加载前返回明确错误。

## 4. 技术方案

### 4.1 处理流程

任务按“参数校验 → 输出目录检查 → 校准数据加载 → 模型加载 → 量化 → 模型保存 → 清单生成”的顺序执行。不同算法共享统一入口、异常处理和输出规范，算法依赖采用延迟导入，便于基础逻辑测试。

### 4.2 算法实现

- **GPTQ**：使用 GPTQModel，适合精度优先场景，需要校准数据，支持 group size 配置。
- **AWQ**：使用 AutoAWQ，当前限定 4 bit；校准数据统一走平台数据加载逻辑，不再依赖硬编码路径。
- **BnB**：使用 Transformers 的 BitsAndBytesConfig，支持 4/8 bit，适合快速试用，不需要校准集。

### 4.3 数据与存储

校准数据优先从 `models-storage`、`models-share-volume` 查找，支持 Dataset/DatasetDict 及常见文本文件。文本列自动识别 `text`、`content`、`prompt`、`instruction` 等字段。输出目录包含量化模型和 `quant_manifest.json`。

### 4.4 可观测性与安全

节点输出 `validate`、`calibration`、`load_model`、`quantize`、`complete` 或 `failed` 阶段事件。结果清单记录参数、运行依赖、耗时、产物数量及异常信息，并采用临时文件原子替换。镜像构建凭据通过环境变量传入，不在脚本中保存明文密码。
