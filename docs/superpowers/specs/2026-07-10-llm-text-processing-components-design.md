# 大模型文本处理组件设计

## 背景与目标

`myapp/init/init-job-template.json` 中的 `nlp-replace-private-data`、`question-answer-generation` 和 `question-answer-extension` 目前只是 `python:3.9` 占位模板，没有对应的可运行代码。

本次交付两个可独立构建和运行的文本处理组件：

1. `nlp-replace-private-data`：对 Markdown 和纯文本中的隐私数据进行稳定、可追踪的脱敏替换。
2. `question-answer-generation-extension`：从 Markdown 和纯文本生成有原文依据的问答对，并同步生成等价问法。

合并后的 `question-answer-generation-extension` 替换 `question-answer-generation` 模板，原 `question-answer-extension` 占位模板删除，避免重复入口。

## 范围

### 包含

- 输入目录递归发现 `.md` 和 `.txt` 文件，扩展名匹配不区分大小写。
- UTF-8 文本读取，支持带 BOM 的 UTF-8 文件。
- OpenAI Chat Completions 兼容接口。
- 通过明确的系统提示词和严格 JSON 响应约束完成语义处理。
- 大文件分块、模型调用重试、响应解析和业务校验。
- Dockerfile、构建脚本、命令行入口、模板参数和自动化测试。
- 处理报告，包括成功、跳过和失败文件/文本块的统计。

### 不包含

- PDF、Word、JSON、JSONL、CSV 或 Parquet 输入。
- OCR、版面恢复或 Markdown 渲染。
- 本地模型推理服务的部署。
- 人工审核界面。
- 把 API 密钥写入镜像、代码或输出文件。

## 方案选择

考虑过以下方案：

1. 整文件一次调用模型：实现最简单，但会受上下文长度限制，失败重试成本高，也难以保证输出结构。
2. 仅按块调用模型：能处理大文件，但隐私组件完全依赖模型改写，容易破坏 Markdown 格式或漏掉规则明确的标识符。
3. 分块模型调用加本地确定性处理：隐私组件先用规则替换高确定性标识符，再让模型返回语义实体列表并由本地完成替换；问答组件让模型按块一次生成问答与泛化结果，再执行严格校验。

采用方案 3。它在模型成本、输出可靠性、格式保持和实现复杂度之间最平衡。

## 共用运行约定

两个组件保持仓库现有的自包含结构，各自位于 `job-template/job/<component-name>/`。每个目录包含自己的启动脚本、模型客户端、提示词、Dockerfile、构建脚本和测试，构建镜像时不依赖相邻组件目录。

### 模型接口

命令行参数统一包含：

- `--base_url`：必填。既接受完整的 `.../chat/completions` 地址，也接受以 `/v1` 结尾的地址；后一种形式自动补全 `/chat/completions`。
- `--api_key`：可选。未提供时读取环境变量 `API_SECRET_KEY`，请求头使用 `Authorization: Bearer <key>`。日志不得输出密钥。
- `--model_name`：必填，作为请求体中的 `model`。
- `--temperature`：可选，隐私识别默认 `0`，问答生成默认 `0.2`。
- `--timeout`：单次请求超时秒数，默认 `120`。
- `--max_retries`：失败后的最大重试次数，默认 `3`。

请求采用非流式 Chat Completions 格式。对 HTTP 408、429 和 5xx、网络异常、响应 JSON 无法解析、模型内容不满足约定等情况执行指数退避重试。超过重试次数后将当前块记入报告，并按组件的降级策略继续处理其他块。

### 文件发现与分块

- `--input_dir` 和 `--output_dir` 均为必填目录参数。
- 文件按相对路径排序后处理，保证同一输入的处理顺序稳定。
- 仅处理普通 `.md`/`.txt` 文件；符号链接不递归跟随。
- 文本优先在空行、换行和句末标点处分块，无法找到自然边界时才按字符数硬切。
- `--chunk_size` 表示单块最大字符数，默认 `6000`，允许范围为 `500` 至 `30000`。
- 空文件不调用模型；隐私组件原样输出，问答组件记录为跳过。

### 结构化模型响应

提示词要求模型只返回 JSON，不输出 Markdown 代码围栏或解释。实现仍兼容代码围栏包裹的 JSON，并从内容中提取第一个合法 JSON 对象。所有字段经过本地类型、空值、数量上限和来源约束校验；校验失败视为可重试错误。

## 组件一：隐私数据替换

### 数据流

1. 读取单个文件并建立文件级占位符映射。
2. 使用本地规则识别并替换高确定性的手机号、电子邮箱、中国大陆身份证号和银行卡号。
3. 将已做规则脱敏的文本分块发送给模型，识别人名、详细地址、账号标识、车辆标识、设备标识及其他上下文隐私。
4. 模型返回实体列表，而不是改写后的全文。
5. 本地校验实体必须逐字存在于对应文本块，忽略空值、占位符本身、过长文本和不支持的类型。
6. 按“文本更长优先、位置从后向前”的顺序替换，避免嵌套实体和位置偏移。
7. 同一文件中相同的“类型 + 原值”复用同一占位符。
8. 使用输入相对路径写入输出目录，保留 `.md`/`.txt` 扩展名和未命中的所有格式内容。

### 占位符规则

占位符采用 `[类型_序号]`，例如 `[姓名_1]`、`[手机号_1]`、`[详细地址_2]`。序号在每个文件、每个类型内从 1 开始。输出报告只记录各类型替换数量，不记录原始值与映射关系。

规则识别先于模型调用，这可以保证常见高风险标识符即使在模型失败时仍被处理。模型看到的是已完成规则脱敏的文本，减少发送到模型服务的明文隐私量。

### 模型提示词约束

系统提示词将模型限定为“隐私实体识别器”，要求：

- 不改写、总结或翻译文本。
- 只识别可用于定位自然人或访问个人资源的信息。
- 普通知识、公开机构名称和泛化地名不作为隐私实体。
- `text` 必须是输入中连续、逐字存在的原文。
- 返回 `{"entities":[{"text":"...","category":"person_name"}]}`。
- 类别只允许 `person_name`、`detailed_address`、`account_id`、`vehicle_id`、`device_id` 和 `other_private`。

### 降级与错误处理

- 某个模型块最终失败时，保留该块已经完成的规则脱敏结果，不回退为原始高风险标识符。
- 单文件读取或写入失败不会中止整个目录，失败路径和错误摘要写入 `processing_report.json`。
- 输出目录不能位于输入目录内部，防止重复扫描自己的输出。

## 组件二：问答生成与泛化

### 数据流

1. 读取文件并按自然边界分块。
2. 对短于 `--min_chunk_chars` 的无有效内容块跳过，默认阈值为 `80`。
3. 每个文本块用一次模型调用生成标准问题、答案、等价问法和原文证据。
4. 校验字段、数量、证据来源和重复项。
5. 以“来源文件 + 标准化问题”为键去重。
6. 将所有文件的结果写入 `qa_pairs.jsonl`，每行一个标准问答记录。

### 输出契约

每条 JSONL 记录包含：

```json
{
  "source_file": "manual/intro.md",
  "chunk_index": 0,
  "question": "如何创建项目？",
  "answer": "在项目页面选择“新建项目”并填写项目名称。",
  "generalized_questions": ["创建一个项目需要怎么操作？", "新项目从哪里建立？"],
  "evidence": "在项目页面选择“新建项目”并填写项目名称。"
}
```

`evidence` 必须是输入块中逐字存在的非空连续片段，否则该问答记录被丢弃。`generalized_questions` 去除空值、与标准问题相同的内容和互相重复的内容，最多保留 `--extensions_per_question` 条。

### 生成参数

- `--questions_per_chunk`：每块最多生成的标准问答数量，默认 `5`，范围 `1` 至 `20`。
- `--extensions_per_question`：每个标准问题最多生成的等价问法数量，默认 `3`，范围 `0` 至 `10`。
- `--min_chunk_chars`：有效块最小字符数，默认 `80`，范围 `1` 至 `--chunk_size`。

### 模型提示词约束

系统提示词将模型限定为“基于证据的数据集构造器”，要求：

- 只能依据提供的文本回答，不使用外部知识，不补全缺失事实。
- 问题必须语义明确、脱离上下文后仍可理解，答案简洁完整。
- 泛化问题只能改变表述方式，不能改变意图、条件或答案。
- 避免“本文说了什么”一类低价值问题、是非题和重复问题。
- 证据必须从输入中原样复制一个连续片段。
- 返回 `{"qa_pairs":[{"question":"...","answer":"...","generalized_questions":["..."],"evidence":"..."}]}`。
- 结果数量不得超过请求参数，文本不支持可靠问答时返回空数组。

### 降级与错误处理

- 某块在重试后仍失败时跳过该块，继续处理同文件和其他文件。
- 不生成没有证据或结构不完整的半成品记录。
- 使用临时文件写入并原子替换最终 `qa_pairs.jsonl`，避免进程失败后留下看似完整的截断文件。
- `processing_report.json` 记录输入文件数、文本块数、有效问答数、跳过块数及失败块摘要。

## 模板变更

`myapp/init/init-job-template.json` 做以下修改：

1. `nlp-replace-private-data` 使用项目镜像仓库地址、`/job-template/job/nlp-replace-private-data` 代码路径、`/app` 工作目录和 `python3 launcher.py` 命令，并配置上述运行参数。
2. 将键和 `job_template_name` 为 `question-answer-generation` 的模板替换为 `question-answer-generation-extension`，描述改为“问答对生成与泛化”。
3. 删除独立的 `question-answer-extension` 占位模板。
4. 后续图像组件的 `index` 不重排；模板索引沿用现有位置，避免无关变更。

镜像标签采用与相邻文本处理组件一致的私有仓库命名约定，组件目录提供独立 `build.sh` 作为发布入口。

## 测试策略

测试使用 Python 标准库 `unittest`，模型调用通过可注入的假客户端完成，不依赖网络或真实密钥。

### 共用行为

- 仅发现 `.md`/`.txt`，忽略其他格式并保持稳定排序。
- 自然边界分块和硬切均不丢失原文字符。
- 模型 URL 规范化、授权头、响应内容提取、重试和错误上限。
- 非法参数在调用模型前失败并给出明确错误。

### 隐私组件

- 手机号、邮箱、身份证号和银行卡号规则替换。
- 重复实体复用占位符，不同实体递增序号。
- 模型实体必须存在于原文才会被替换。
- Markdown 标记和目录结构保持不变。
- 模型失败时仍输出规则脱敏结果。
- 报告不包含原始隐私值和 API 密钥。

### 问答组件

- 合法结构写成约定的 JSONL 字段。
- 无原文证据、空字段和超量结果被过滤。
- 泛化问题去重并执行数量上限。
- 跨重叠块的标准问题去重。
- 单块失败不影响其他块，报告统计正确。
- 输出通过临时文件原子落盘。

### 模板与静态验证

- `init-job-template.json` 能被标准 JSON 解析器加载。
- 两个新模板的参数、代码路径、工作目录和命令与启动脚本一致。
- 不再存在 `question-answer-generation` 和 `question-answer-extension` 模板键。
- 目录中不存在真实密钥、示例密钥或构建产物。

## 验收标准

- 两个组件可通过命令行独立处理包含多个层级目录的 `.md`/`.txt` 输入。
- 隐私组件在模型成功时完成规则和语义隐私替换，在模型失败时至少完成规则隐私替换，且保持原文结构。
- 问答组件输出同时包含标准问题和等价问法，所有记录具有可在输入中定位的证据。
- 模型异常不会导致整个批处理提前中止，报告能够定位失败文件或文本块。
- 自动化测试全部通过，模板 JSON 解析和命令帮助检查通过。
