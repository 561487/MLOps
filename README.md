# MLOPS 平台

MLOPS 平台是一套面向企业 AI 研发和生产交付的一站式机器学习平台，覆盖数据准备、在线开发、模型训练、任务编排、模型管理、推理服务、资源监控和运维治理等完整流程。平台以 Kubernetes 为底座，统一管理 CPU、GPU、存储、镜像、任务和服务，让算法工程师、数据工程师、平台运维和业务团队可以在同一套系统中协作完成模型从开发到上线的全生命周期管理。

平台的目标是降低 AI 工程化门槛：用户不需要直接操作 Kubernetes、容器、工作流引擎和推理服务组件，只需要在 Web 控制台中选择资源、镜像、数据、模板和运行参数，即可完成开发环境创建、训练任务提交、Pipeline 编排、模型注册和服务发布。

## 平台定位

平台主要解决 AI 研发生产中的四类问题：

- 资源统一管理：将多集群、多租户、CPU、GPU、存储和网络资源纳入统一调度和配额体系。
- 开发训练标准化：通过 Notebook、镜像、任务模板和 Pipeline 固化研发流程，减少重复环境搭建。
- 模型资产沉淀：统一管理数据集、训练产物、模型版本、评估结果和模型市场。
- 服务上线闭环：支持模型部署、弹性伸缩、监控告警、日志追踪和运行状态管理。

## 核心能力

### 资源与权限

平台支持项目组、用户、角色、权限、资源组和多集群管理。管理员可以为不同团队分配 CPU、内存、GPU、存储和任务并发额度，并通过平台记录资源申请、使用、释放和计费信息。

资源治理能力包括：

- 项目组和租户隔离。
- 用户、角色、菜单和操作权限控制。
- CPU、内存、GPU、vGPU、存储等资源配额。
- 多 Kubernetes 集群和多资源组管理。
- 任务、Notebook、服务维度的资源用量统计。
- GPU 节点、Pod、服务和任务运行状态监控。

### 在线开发

平台提供在线 Notebook 和远程开发环境，支持 Jupyter、VSCode 等交互式开发方式。用户可以选择 CPU/GPU 资源、基础镜像、挂载数据和代码目录，快速创建可复现的开发环境。

在线开发能力包括：

- Notebook 生命周期管理。
- CPU/GPU 资源规格选择。
- 自定义 Notebook 镜像。
- 数据集、模型目录和共享存储挂载。
- Web 终端、日志、资源监控和调试入口。
- 开发环境保存和复用。

### 镜像与环境

平台将镜像作为算法运行环境的标准载体，支持基础镜像、Notebook 镜像、训练镜像、推理镜像和任务模板镜像的统一管理。用户可以通过平台注册镜像，也可以基于 Dockerfile 在线构建镜像。

镜像体系覆盖：

- Python、机器学习、深度学习、大数据等基础环境。
- CUDA、cuDNN、GPU 驱动适配的训练环境。
- Jupyter、VSCode 等在线开发环境。
- TensorFlow Serving、TorchServe、Triton 等推理环境。
- 自定义算法、数据处理和大模型工具镜像。

### 数据与特征

平台支持数据集、数据处理任务和 ETL Pipeline 管理，可将离线数据、标注数据、训练样本和特征处理流程统一纳入平台。用户可以围绕项目沉淀数据资产，并在训练、评估和推理流程中复用。

数据能力包括：

- 数据集上传、挂载、导入和版本管理。
- 图片、音频、文本、表格等多类型数据管理。
- 数据同步、数据清洗、特征处理和样本拆分。
- ETL Pipeline 编排和调度。
- SQL 查询和元数据管理。

### 训练与任务编排

平台提供标准任务模板和可视化 Pipeline 编排能力，用户可以通过拖拽方式组合数据处理、模型训练、模型评估、模型注册和服务发布节点。底层任务运行在 Kubernetes 上，由工作流引擎统一调度。

训练能力包括：

- 单机训练、分布式训练和批调度任务。
- PyTorch、TensorFlow、Ray、Volcano 等训练模式。
- NNI、Ray 等自动调参和超参搜索。
- Pipeline 定时调度、补录、重试、暂停和恢复。
- 任务输入输出、全局变量和运行结果可视化。
- 任务日志、资源监控和运行历史追踪。

### 模型管理

平台将训练产物转化为可管理、可复用、可发布的模型资产。模型可以按项目、算法、版本、指标和来源进行归档，并与评估结果、训练任务和推理服务建立关联。

模型管理能力包括：

- 模型注册和版本管理。
- 模型文件、配置、指标和说明信息维护。
- 模型评估和评估报告沉淀。
- 模型市场和模型资产复用。
- 训练任务到模型版本的链路追踪。
- 模型到推理服务的发布管理。

### 推理服务

平台支持将模型一键发布为在线推理服务，提供服务实例、版本、资源、域名、端口、健康检查、弹性伸缩和监控配置。用户可以基于通用推理镜像或自定义镜像部署服务。

推理服务能力包括：

- 常规模型和大模型推理服务发布。
- CPU/GPU/vGPU 资源规格配置。
- 多版本服务、滚动升级和回滚。
- 服务域名、端口、环境变量和配置挂载。
- 健康检查、日志查看和指标监控。
- QPS、延迟、资源使用率等运行指标采集。

### 大模型工具链

平台内置大模型相关任务模板，支持围绕大语言模型的下载、离线推理、量化、剪枝、蒸馏、评估和服务化流程。用户可以通过任务模板快速发起标准化大模型处理任务。

大模型能力包括：

- 模型下载和模型目录管理。
- LLM 离线批量推理。
- GPTQ、AWQ、RTN 等量化流程。
- 结构化剪枝、注意力头剪枝和层级裁剪。
- 模型蒸馏和训练数据处理。
- 大模型推理服务部署。

### 运维与监控

平台提供面向任务、服务、节点和集群的监控视图，帮助管理员了解资源使用情况、定位异常任务、追踪服务状态和分析平台负载。

运维能力包括：

- 集群节点资源监控。
- GPU 使用率、显存、温度和设备状态监控。
- Pod、任务、Notebook、服务运行状态监控。
- 任务日志、事件和失败原因查看。
- 平台定时清理、状态同步和后台任务管理。
- 离线环境下的镜像同步和私有仓库适配。

## 平台架构

平台采用前后端分离和云原生架构，整体分为接入层、平台服务层、调度执行层、基础设施层和数据存储层。

```text
用户
  │
  ▼
Web 控制台
  │
  ▼
平台服务层
  ├── 用户权限与项目管理
  ├── Notebook 与镜像管理
  ├── Pipeline 与任务管理
  ├── 模型与数据集管理
  ├── 推理服务管理
  └── 资源监控与运维管理
  │
  ▼
调度执行层
  ├── Kubernetes
  ├── 工作流调度
  ├── 分布式训练
  ├── 批调度
  └── 服务网关
  │
  ▼
基础设施层
  ├── CPU / GPU 节点
  ├── 共享存储
  ├── 镜像仓库
  ├── 对象存储
  ├── 监控系统
  └── 数据库与缓存
```

平台后端负责业务编排、权限控制、元数据管理和 Kubernetes 资源生成；前端负责提供统一控制台和可视化 Pipeline 编排；底层 Kubernetes 负责实际的容器调度、资源隔离、任务执行和服务运行。

## 典型使用流程

### 模型开发流程

1. 管理员创建项目组并分配资源额度。
2. 用户选择镜像、资源规格和数据目录，创建 Notebook。
3. 用户在 Notebook 中完成数据探索、代码开发和实验验证。
4. 用户将稳定代码封装为镜像或任务模板。
5. 用户提交训练任务或编排 Pipeline。
6. 平台记录任务日志、资源使用和训练产物。

### 模型训练流程

1. 选择训练模板或自定义镜像。
2. 配置输入数据、输出目录、启动命令和运行参数。
3. 选择 CPU/GPU 资源、队列、优先级和超时时间。
4. 提交任务后由平台调度到 Kubernetes 集群执行。
5. 在平台查看日志、事件、指标和运行结果。
6. 训练完成后将产物注册为模型版本。

### 模型上线流程

1. 在模型管理中选择目标模型版本。
2. 选择推理镜像、启动命令、端口和资源规格。
3. 配置服务域名、环境变量、健康检查和伸缩策略。
4. 发布推理服务并观察实例状态。
5. 通过监控查看 QPS、延迟、错误率和资源使用率。
6. 后续可进行版本升级、回滚或下线。

## 角色分工

- 平台管理员：负责集群、资源、权限、镜像仓库、监控和平台配置。
- 算法工程师：负责 Notebook 开发、模型训练、模型评估和模型注册。
- 数据工程师：负责数据集管理、ETL Pipeline 和特征处理流程。
- 运维工程师：负责服务稳定性、资源监控、故障定位和离线环境维护。
- 业务用户：通过模型市场或推理服务使用平台沉淀的模型能力。

## 运行环境

平台运行在 Kubernetes 集群之上，依赖容器运行时、共享存储、对象存储、数据库、缓存、镜像仓库和监控组件。生产环境建议按控制节点、训练节点、推理节点和存储资源进行规划，并根据业务规模扩展 GPU、CPU 和存储容量。

基础依赖包括：

- Kubernetes 集群。
- Docker 或 containerd 容器运行时。
- MySQL 元数据库。
- Redis 缓存和异步任务队列。
- MinIO 或兼容 S3 的对象存储。
- NFS、Ceph、JuiceFS 或其他共享文件系统。
- Prometheus 和 Grafana 监控体系。
- Harbor 或其他私有镜像仓库。

## 适用场景

平台适用于需要统一管理 AI 研发、训练、推理和运维流程的团队，尤其适合以下场景：

- 企业内部 AI 中台建设。
- 多团队共享 GPU 集群。
- 机器学习和深度学习任务统一调度。
- 训练任务、数据处理任务和模型服务的标准化交付。
- 大模型微调、压缩、评估和推理服务化。
- 内网或私有化环境下的模型研发生产闭环。
